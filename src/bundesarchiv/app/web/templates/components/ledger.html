{% comment %} Ledger organism — the results register. A dense, aligned alternative to the card list. Params: - rows — list of dicts, each carrying a ledger_row's params (title, href, ref_code, datierung, typ, draft, visibility, action_label, action_href) - columns — list of column headers {label, key, sortable, [query, active, order]}. Sortable heads (sortable=True) are links whose href is the header's NEXT sort state (asc→desc→default cycle, computed in the view); the active column shows ▲ (asc) / ▼ (desc). Non-sortable heads (sortable=False, e.g. Typ) are plain labels. URL-as-state, no JS — the sort control IS the headers (there is no sort select). - narrow (bool) — density mode: full (aligned columns, default) vs narrow (two-line compact rows, the mail-client fold: line 1 = SIG + Titel, line 2 = Datierung · Typ). The class swap is the ONLY difference — same rows, CSS reflows the grid. - archivist (bool) — archivist chrome. When true (default), the SICHTBARKEIT column (visibility badge / ENTWURF) and the row action gutter render. For members/public it is FALSE, so those two columns are omitted entirely (header + every row cell), and the grid drops to the four member-visible columns. This is presentation gating; the SICHTBARKEIT data itself never rides to a non-archivist (search()/SearchHit already scope the rows). Every column head — sortable or not — uses the ONE label type role (small-caps, letterspaced, on-surface-variant), identical size/case/weight/color. The only systematic modifiers on that base: sortable heads get the link affordance (ink + underline on HOVER, stamp-grammar link rule); the active sort column gets exactly one direction glyph (▲/▼), never a different font treatment. Body marks (SIG codes, Datierung) carry ink per the stamp grammar; everything else is neutral chrome. {% endcomment %}
