{% comment %} The rail's FILTER SET — one facet_group dropdown per group, then the active-filter chips, then clear-all. Split out of _filterrail.html for ONE reason: it is the unit an htmx q-swap has to refresh out-of-band. Every link here is built from the request's query params, so after a live q-swap (which only replaces #results) a rail rendered by the PREVIOUS request describes a query the URL no longer has — the chip ✕ then navigated to "?" and destroyed the typed search. On an HX-Request the view sets oob=True and _results.html emits this same include as a top-level hx-swap-oob fragment, so counts, aria-current and every href refresh together. A dropdown left open across a q-swap closes with the swap. That is the honest outcome, not a regression: its counts and links were rendered for the previous query, and showing a stale open panel is exactly the defect this fragment exists to kill. Why this is its own element and not the whole
: the count's aria-live node must SURVIVE the swap (a live region inserted together with its content is not announced), so #trefferzahl stays outside the swapped subtree and keeps its own innerHTML oob. The div is a pure swap handle with display: contents (layouts.css) — its children are the rail's flex items exactly as before, so the grouping costs no box and no composition change. {% endcomment %}
